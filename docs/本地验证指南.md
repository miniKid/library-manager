# 本地验证指南（不部署也能验）

> 面向：在自己电脑上用「微信开发者工具」跑这个项目，想确认第二期五个功能是否正常。

---

## 0. 先分清三件事

之前那三步之所以看不懂，是因为它们混了「改代码」和「在云上建东西」两件完全不同的事：

| 说法 | 实际动作 | 在哪做 | 什么时候需要 |
|---|---|---|---|
| 改 `useCloud` | 把配置文件里一个开关改成 `false` | 你自己电脑的编辑器 | 想**不部署**先看效果 |
| 建集合 | 在云数据库里建 4 张"表" | 云开发控制台（浏览器/工具内） | 用云端真实数据时 |
| 部署云函数 | 把 `cloudfunctions/xxx` 的代码上传到云端运行 | 开发者工具左侧文件树右键 | 用云端真实数据时 |

**关键结论：如果只是想看功能长什么样、点得动点不动，完全不用建集合、不用部署云函数。** 走下面的方式 A 就行。

本项目有两种运行模式，由 `miniprogram/config/env.js` 第 12 行决定：

```js
useCloud: true,   // 走云端（需要集合 + 云函数）
useCloud: false,  // 走本地模拟数据（全部逻辑在小程序里跑，零部署）
```

---

## 方式 A：模拟模式（推荐先做，约 5 分钟）

### A1. 打开开关

用编辑器打开 `miniprogram/config/env.js`，把第 12 行改成：

```js
useCloud: false,
```

保存（`Ctrl/Cmd + S`）。

### A2. 清掉旧缓存（重要，别跳过）

模拟数据存在小程序的 Storage 里，旧版本没有 `reviews` / `notifications` / `todos` 这几张"表"，不清会读到半新半旧的数据。

开发者工具顶部菜单：**工具 → 清缓存 → 清除数据缓存**（全部勾上）。

### A3. 点「编译」

工具栏左侧的「编译」按钮，或 `Ctrl/Cmd + B`。

### A4. 第一个登录的人自动是管理员

- 底部 tab 进「我的」→ 点「立即登录」→ 允许获取头像昵称
- 模拟模式规则：**库里还没有管理员时，第一个登录的用户自动成为管理员**
- 登录后「我的」页应该出现「🔔 消息通知 / ✅ 我的待办 / ✨ 为你推荐」三个入口
- 底部 tab 的「管理」能看到 8 个菜单（图书管理…书评管理）

> 如果你已经不是管理员了（之前登录过别的账号），重复 A2 清缓存 → A3 编译 → A4 重新登录。

### A5. 按第 3 节清单逐项点

模拟模式下**订阅消息（微信服务通知）不会发**，站内通知会正常写。

## 方式 B：真云开发（要上线 / 要验云函数代码时才做，约 20 分钟）

### B1. 确认 AppID 和云环境

- `project.config.json` 里的 `appid` 应是你自己的（现在是 `wxc53b60cd4ac3f305`）
- 点工具栏「云开发」→ 首次会提示开通 → 开通后记下**环境 ID**
- 把环境 ID 填进 `miniprogram/config/env.js` 的 `cloudEnv`，并把 `useCloud` 改回 `true`

### B2. 建 4 个集合

云开发控制台 → 左侧「数据库」→ 集合名称右边「**+**」→ 输入名字 → 创建。重复 4 次：

`reviews`　`notifications`　`todos`　`noticeLogs`

每建一个，点该集合右上角「**权限设置**」→ 选「**所有用户不可读写**」→ 保存。

> 为什么不是「所有人可读」：这 4 张表里有别人的借阅和留言。设成不可读写后，小程序端只能通过云函数访问（云函数有管理员校验），前端直接查是查不到的。

### B3. 建索引

云开发控制台 → 数据库 → 点集合名 → 「**索引管理**」→ 添加索引。按下表填（字段名区分大小写）：

| 集合 | 索引字段（顺序不能乱） | 说明 |
|---|---|---|
| `reviews` | `bookId` 升序 + `status` 升序 + `createdAt` 降序 | 书籍详情页取书评 |
| `reviews` | `openid` 升序 + `bookId` 升序 | 判断"我评过没" |
| `notifications` | `toOpenid` 升序 + `read` 升序 + `createdAt` 降序 | 消息中心列表 |
| `todos` | `ownerOpenid` 升序 + `done` 升序 + `dueDate` 升序 | 待办列表 |
| `noticeLogs` | `createdAt` 降序 | 群发记录 |

> 索引不是"必须"，但不建的话数据一多列表会变慢，控制台也会提示缺索引。

### B4. 部署 4 个云函数

在开发者工具**左侧文件树** → `cloudfunctions` 目录：

1. 先右键 `cloudfunctions` 根节点 → 「**当前环境**」→ 选中你的环境（不选会报 `env check invalid`）
2. 右键 `reviewManager` → 「**上传并部署：云端安装依赖（不上传 node_modules）**」
3. 对 `notifyManager`、`insightManager` 重复
4. **重点**：`notify` 也要重新部署一次（它被改造过，现在除了发订阅消息还会写站内通知）

看到右下角提示"上传成功"即可。4 个函数大约 1–2 分钟。

> `notify` 有定时触发器（每天 9:00），部署后到 云开发控制台 → 云函数 → `notify` → 触发器，确认有一条 `dailyReturnRemind`；没有就点「创建触发器」，Cron 填 `0 0 9 * * *`。

### B5. 初始化数据（第一次必做）

开发者工具 → 右键 `initDB` → 「上传并部署：云端安装依赖」→ 然后到 **云开发控制台 → 云函数 → `initDB` → 测试** → 参数填 `{}` → 运行。

返回 `"初始化完成，已写入 N 本种子图书"` 就对了。

> ⚠️ **我这次改了一处**：`initDB` 原来写死了作者的 openid 当作管理员，照原样部署会导致**你永远进不去管理端**（`login` 的规则是"配了 adminOpenid 就只认这一个人"）。现在已改成空字符串，含义是"第一个登录的人当管理员"。

### B6. 验证管理员身份

回到开发者工具点「编译」→ 我的 → 登录。第一个登录的用户就是管理员，底部 tab 出现「管理」。

如果登录后仍不是管理员，去 云开发控制台 → 数据库 → `settings` → 集合里那条 `_id: global` 的记录，确认 `adminOpenid` 是空字符串。

## 3. 验收清单（两种模式都适用）

逐条点，对照"预期"。真实结果与预期不符时，看第 4 节。

### ① 通知（需求 1）

| 步骤 | 预期 |
|---|---|
| 管理 tab → 发送通知 → 发送范围选「全部用户」，通知内容填标题"测试公告"、正文随便写 → 点「发送通知」 | 提示发送成功，下方「发送记录」多一条，显示触达人数 |
| 底部 tab「我的」→ 看「🔔 消息通知」 | 右侧出现红色数字角标 |
| 点进去 | 列表里能看到"测试公告"，未读的有点/加粗 |
| 点右上「全部已读」 | 角标消失，列表项变灰 |
| 点「只看未读 / 全部通知」切换 | 能过滤未读 |
| 点右上「通知设置」→ 关掉「借阅」→ 保存 | 之后确认借出不再产生借阅类通知 |
| 下拉 | 能刷新（页面支持下拉刷新） |

### ② 待办（需求 1）

| 步骤 | 预期 |
|---|---|
| 我的 → ✅ 我的待办（或消息中心切到「待办」tab） | 分「系统提醒」「我的待办」「已完成」三块 |
| 点「+ 新建待办」→ 标题"还书"、截止日期选明天、优先级高 → 保存 | 出现在「我的待办」，带红色"高"标签和日期 |
| 勾选它（左侧圆圈） | 移到「已完成」 |
| 点右侧「×」 | 从列表消失 |
| 有逾期未还的书时看「系统提醒」 | 出现"逾期 N 天"这类自动待办（不需要手动建） |

### ③ 书评（需求 4）

| 步骤 | 预期 |
|---|---|
| 首页点任意一本书 → 详情页往下滑 | 出现「读者书评」卡片，显示平均分和条数（初始显示"还没有书评，来说说你的感受"） |
| 点卡片右上「写第一条 ›」→ 进入书评页 → 点顶部「写书评」→ 选 4 星 → 写 20 个字 → 提交 | 提示成功；返回详情页概览变成 4.0 分 / 1 人评价 |
| 再点一次顶部 | 变成「修改我的书评」（同一本书只能写一条，不会重复发） |
| 进「全部书评」页 | 能看到刚才那条，可点赞、可删除自己的 |
| 管理 tab → 书评管理 → 对该条点「隐藏」 | 详情页平均分和条数**同步减少**（隐藏的不计入评分） |
| 管理端点「回复」→ 输入"感谢反馈" | 回到用户端书评页，该条下方出现馆员回复；同时该用户「消息通知」多一条 |

### ④ 推荐（需求 5）

| 步骤 | 预期 |
|---|---|
| 首页「图书列表」上方 | 出现「✨ 为你推荐」横滑卡片，每本带一句推荐理由（如"你常借文学类"） |
| 点「更多 ›」 | 进入推荐列表页，可「换一批」 |
| 借过一本书后再看推荐 | 那本书不再出现在推荐里 |

> 模拟模式种子数据少，推荐理由可能多是"热门/高分/新书"这类冷启动话术，属正常。

### ⑤ 统计与导出（需求 2、3）

| 步骤 | 预期 |
|---|---|
| 管理 tab → 数据统计 | 默认「用户统计」，显示注册用户/有效借书证/人均借阅、馆藏地点分布、每日新增用户、借阅排行 TOP20 |
| 切「书籍统计」 | 显示书籍种类/馆藏总册/在架可借、分类分布、评分分布、借阅热度 TOP20 |

> 导出的 CSV 带 BOM，用 Excel 直接打开中文不乱码；手机号中间四位是 `****`。

### ⑥ 数据一致性抽查

| 检查 | 预期 |
|---|---|
| 详情页「可借 N 本」 vs 书籍统计「在架可借」合计 | 口径一致，不会一个说有货一个说没货 |

## 4. 常见报错对照

| 现象 | 原因 | 处理 |
|---|---|---|
| `cloud function not found` / `-501000` | 云函数没部署，或部署到了别的环境 | B4 重新部署，注意先选「当前环境」 |
| `database collection not exists` | 集合没建 | B2 |
| `permission denied` / `-502003` | 集合权限不是「所有用户不可读写」 | B2 改权限 |
| `env check invalid` | `cloudEnv` 写错，或云函数部署环境与小程序环境不同 | 核对 `env.js` 的 `cloudEnv` 与控制台环境 ID |
| 页面白屏 / 列表显示 `NaN` | 旧 Storage 数据结构缺新字段 | A2 清缓存重编译 |
| 进不去管理端 | `settings.global.adminOpenid` 填了别人的 openid | B6 |
| 导出没反应 | 模拟器不支持转发文件，降级为剪贴板；剪贴板也失败时看控制台报错 | 真机测，或直接看 Console |
| 书评提交提示"包含敏感词" | 本地词库预检拦截 | 换词；词库在 `cloudfunctions/reviewManager/index.js` |

## 6. 建议的顺序

1. 先走 **方式 A**，把第 3 节清单过一遍 —— 这一步能发现 90% 的界面/逻辑问题，成本 5 分钟
2. 界面都对了，再走 **方式 B**，重点验三件模拟模式验不了的事：
   - 微信服务通知（订阅消息）能不能收到
   - `notify` 定时器每天 9:00 有没有跑
   - 云端权限是否真的挡住了前端直查（在控制台"数据库 → 集合 → 数据"里能看，前端查不到）
