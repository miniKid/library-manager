# 云图图书馆 · 第二期功能需求规格说明

> 版本：v1.0 ｜ 分支：`feature/optimize` ｜ 基线：`main@993ab9c`  
> 本文档为「先补全需求、再落地代码」的产出：每条需求都写清了**业务规则、边界条件、验收标准**，并直接对应到实现中的集合字段与云函数 action。

---

## 1. 背景与范围

现有系统是「微信小程序 + 云开发」的双端图书借阅系统：用户端可查书、预约借还、续借；管理端可管书、审批借书证、确认借还、配置馆藏与值班。

本期在其上新增 5 个能力，覆盖「**触达**（通知/待办）→ **沉淀**（评论/评分）→ **发现**（推荐）→ **运营**（统计/导出）」的闭环：

| 编号 | 功能        | 主要使用方      | 价值                        |
| -- | --------- | ---------- | ------------------------- |
| F1 | 通知中心 + 待办 | 全部用户 / 管理员 | 把「到期、审批、待确认」从用户主动查询变为被动触达 |
| F2 | 用户统计与导出   | 管理员        | 看清用户规模、结构、活跃度，可导出存档/上报    |
| F3 | 书籍统计与导出   | 管理员        | 看清馆藏结构、借阅热度、滞销书，指导采购      |
| F4 | 书籍评论区     | 全部用户 / 管理员 | 沉淀阅读感想，形成选书参考，提升留存        |
| F5 | 书籍推荐栏目    | 全部用户       | 解决「不知道借什么」，提升借阅转化         |

**不做的范围**（明确排除，避免误解）：

- 不做独立 Web 后台，管理能力仍在小程序「管理」Tab 内。
- 不做即时聊天、私信；评论仅支持管理员回复。
- 不做图片上传评论（云存储私有 + 流量成本，二期再议）。
- 不做自定义定时任务的自由配置；到期/逾期提醒仍由既有 `notify` 定时器驱动。

## 2. 现状约束（实现必须遵守）

1. **客户端不直连数据库**（P0 整改后已全量落地）：`borrows` 的查询已收回云函数（`adminBorrows` / `bookBorrows`），客户端只直连 `books`（书架与详情展示需要）。权限基准见仓库根目录 `database.rules.json`：`books` 可读，`borrows` / `users` / `settings` 及其余集合一律「所有用户不可读写」，全部经 `callFunction` 访问。
2. **云函数按 `event.action` 分发**，身份一律取 `cloud.getWXContext().OPENID`，绝不信任客户端传入的用户标识。
3. **返回结构统一** `{ ok, msg?, data? }`（列表类可返回 `{ ok, data: { list, total } }`）。
4. **服务层双实现**：`services/cloud.js`（云）与 `services/mock.js`（本地模拟）必须导出**同名同签名**方法——仓库自带静态检查会强制这一点，缺一个就红。
5. **时间统一按东八区格式化**（`formatCST` / `cstDateStr`），日期字段存 `Date` 类型，展示层输出 `xxxText`。

## 4. 功能需求

### F1 通知中心 + 待办

#### F1.1 站内通知

**用户故事**：作为读者，我希望在小程序里看到「图书即将到期」「借书证已通过」「预约的取书日期到了」，不用自己记。

**通知类型与触发源**

| type      | 触发时机                        | 标题示例          | 跳转          |
| --------- | --------------------------- | ------------- | ----------- |
| `borrow`  | 借阅申请提交成功、管理员确认借出            | 借阅成功          | 我的借阅        |
| `due`     | 定时器：应还日期前 3 天               | 《三体》将于 3 天后到期 | 我的借阅        |
| `overdue` | 定时器：已过应还日期的首日；管理员手动提醒时同步写一条 | 《三体》已逾期 2 天   | 我的借阅        |
| `card`    | 借书证审批通过 / 驳回                | 借书证已开通        | 我的          |
| `system`  | 管理员群发                       | 自定义           | 自定义（可选页面路径） |
| `review`  | 管理员回复了你的书评                  | 管理员回复了你的书评    | 书籍详情        |

**业务规则**

1. 通知**按人扇出**：发送时给每个接收者写一条独立文档，`read` 独立。接收者上限 500/次（超出截断并提示）。
2. 未读判定 = `read === false`；「全部已读」为批量 `update`。
3. 通知保留 90 天，超期由定时器清理（按 `createdAt` 批量删除，单次最多 200 条）。
4. 用户可在「通知设置」里按 type 关闭**站内通知的创建**；关闭后不再为该类型写文档（历史记录保留）。`system` 类不可关闭。
5. 微信订阅消息（`subscribeMessage.send`）沿用现有 3 个模板，与站内通知互不替代：站内通知保证「打开小程序能看到」，订阅消息保证「关掉小程序也能收到」。

**验收标准**

- 管理员群发后，目标用户打开消息中心能看到，未读数 +1，点击后变已读并跳转正确页面。
- 关闭 `due` 类型后，定时器不再为该用户写 `due` 通知，其余类型不受影响。
- 未登录用户进入消息中心，提示登录，不报错。

#### F1.2 待办

**用户故事**：作为读者/管理员，我希望有一个清单告诉我「今天必须做什么」，并能自己加待办。

**待办分两类**

- **系统待办（自动生成，只读）**：每次进入页面实时计算，不落库，避免数据不一致。
  - 读者：`borrowing` 且 3 天内到期 → 「《X》还有 N 天到期」；已逾期 → 「《X》已逾期 N 天，请尽快归还」；`return_requested` → 「等待管理员确认归还」；`pending` 且 `scheduledPickupDate` 为今天 → 「今天到馆取书」。
  - 管理员：借书证待审批 N 件、借出待确认 N 件、归还待确认 N 件、逾期未处理 N 件（数量为 0 不展示）。
- **自定义待办（可增删改）**：`todos` 集合，字段 `title`（必填，≤30 字）、`note`（≤200 字）、`dueDate`（可选）、`priority`（high/normal/low）、`done`。

**业务规则**

1. 自定义待办按 `dueDate` 升序、无日期排后；已完成的收在「已完成」折叠区。
2. 逾期未完成的待办标红并显示「已逾期 N 天」。
3. 系统待办不可勾选完成，只能通过完成对应业务动作消失（如确认归还）。
4. 每人最多 100 条未完成待办，超出提示清理。

**验收标准**

- 借出一本书后，「我的待办」自动出现到期提醒项，且日期与 `dueDate` 一致。
- 新增待办选「高优先级 + 今天」，列表置顶并显示红色标记；勾选后进入已完成区。
- 管理员待办中的「待审批 N 件」点击直达借书证审批列表。

### F2 用户统计与导出

**用户故事**：作为馆长，我要知道现在有多少注册用户、多少有效借书证、谁最活跃，并能导出成表。

**时间区间（F2 / F3 共用同一套口径）**

| 项 | 规则 |
| --- | --- |
| 预设 | 近 7 天 / 近 30 天 / 近 90 天，默认近 30 天 |
| 自定义 | 起止日期选择器，**含首含尾**（开始日 00:00 至结束日次日 00:00） |
| 上界 | 结束日期 ≤ 今天；开始日期 ≥ 两年前的今天；跨度 ≤ 731 天 |
| 越界处理 | 一律**收敛**而非报错（结束晚于今天→今天；开始早于两年前→两年前；开始晚于结束→自动调换；超长→截断），并回一条 `notices` 文案由页面 toast 提示 |
| 趋势粒度 | 区间 ≤31 天按天、≤120 天按周（7 天一格）、更长按月（自然月），标题标注「按天/按周/按月」 |
| 复用 | 切换 Tab 保留当前区间；导出与页面同一区间，避免「看到的数 ≠ 导出的数」 |
| 校验 | 前端限制 + 云函数二次校验（防止反编译伪造越界参数） |

**指标口径**（必须与页面文案一致）

| 指标          | 口径                                     |
| ----------- | -------------------------------------- |
| 注册用户总数      | `users` 全表 count                       |
| 有效借书证       | `users.card.status === 'active'`       |
| 待审批         | `users.card.status === 'pending'`      |
| 新增用户（区间内） | `createdAt ∈ [开始日 00:00, 结束日次日 00:00)`，预设默认近 30 天         |
| 活跃借阅人       | 区间内有 ≥1 条 `borrows` 记录（不含 `cancelled`） |
| 人均借阅        | 区间内借阅总数 ÷ 活跃借阅人数（活跃为 0 时显示 0）          |
| 零借阅用户       | 从未产生过 `borrows` 记录的持卡用户                |
| 借阅排行        | 区间内按 `userId` 聚合计数降序，取 TOP 20          |
| 馆藏分布        | 按 `users.card.location` 分组             |

**交付形式**

1. 顶部 4 个概览卡：注册总数 / 有效借书证 / 区间新增 / 人均借阅。
2. 结构图：按馆藏地点、按角色、按借阅次数分档（0 / 1-2 / 3-5 / 6+）各一组条形图（纯 CSS，不引图表库）。
3. 趋势：区间内新增用户，按天/周/月分桶（折线用条形模拟）。
4. 榜单：借阅 TOP 20（昵称、借书证状态、借阅次数）。
5. **导出 CSV**：`用户统计_YYYYMMDD-YYYYMMDD.csv`（起止日期取自当前区间），字段：昵称、角色、借书证状态、归属馆藏、手机号（脱敏中间四位）、注册时间、累计借阅次数、区间借阅次数、最近借阅时间。上限 3000 行，超出提示「请缩小范围」。

> 实现说明（小程序无法直接下载到电脑）：CSV 先写入 `USER_DATA_PATH/export/`，再调用 `wx.shareFileMessage` 唤起「转发文件」，转发到文件传输助手即可在电脑打开；基础库不支持时降级为把内容复制到剪贴板。逻辑统一放在 `miniprogram/services/export.js`，云/模拟两种模式共用。

**验收标准**

- 页面数字与「管理首页」的 `memberTotal` 一致（同一口径）。
- 导出的 CSV 用 Excel 打开中文不乱码（UTF-8 BOM）。
- 非管理员访问该页面：入口不可见；即使拼接路径进入，云函数返回「无权限」。

### F3 书籍统计与导出

**指标口径**

| 指标          | 口径                                             |
| ----------- | ---------------------------------------------- |
| 书籍种类        | `books` 全表 count                               |
| 馆藏总册数       | 各书 `stocks` 求和                                 |
| 在架可借册数      | 各书 `stocks` 求和 − 未归还占用（与详情页「可借」同口径）            |
| 分类分布        | 按 `category` 分组计数                              |
| 馆藏地点分布      | 按 `stocks` 各地点求和                               |
| 借阅热度 TOP 20 | 区间内按 `bookId` 聚合计数；无记录时回退 `books.borrowCount`  |
| 滞销书         | `borrowCount === 0` 且上架 > 30 天，按上架时间升序取 TOP 20 |
| 评分分布        | `reviews` 中 `status='approved'` 的 1-5 星计数      |
| 新增书籍（区间内） | `createdAt ∈ [开始日 00:00, 结束日次日 00:00)`（区间规则见 F2）        |

**交付形式**：6 个指标卡 + 分类/地点/热度/评分四组图 + 滞销清单 + 导出 CSV。  
**导出字段**：书名、作者、ISBN、分类、出版社、出版年、馆藏总册、可借册数、累计借阅、平均评分、评论数、上架时间。

**验收标准**

- 「在架可借册数」与各书详情页「可借 N 本」之和一致。
- 导出行数与「书籍种类」一致（≤3000）。

### F4 书籍评论区

**用户故事**：作为读者，我想在书下留一句感想，也想看别人怎么说，决定要不要借。

**核心规则**

1. **一人一书一条**：同一用户对同一本书只有一条评论，重复提交视为**编辑**（保留原 `createdAt`，刷新 `updatedAt`），避免刷屏。
2. **必须登录**；未登录点击「写评论」→ 引导登录。
3. 评分必填（1-5 星），内容 5-500 字；内容做本地敏感词预检（命中直接拒绝并提示），后续可接 `security.msgSecCheck`。
4. **先发后审**：默认 `approved` 直接展示；管理员可 `hide`（前端立即不再展示，评分重算）。
5. **匿名选项**：勾选后列表显示「匿名读者」，服务端对昵称做脱敏（保留首字 + `**`），但后台仍可追溯 openid。
6. **点赞**：每人每条最多 1 次，可取消；`likeCount` 原子 `inc`。
7. **管理员回复**：每条评论最多 1 条官方回复（≤200 字），回复后给作者发 `review` 通知。
8. 聚合回写：任一评论新增/编辑/隐藏后，重算该书 `ratingCount`、`ratingAvg`（保留 1 位小数）、`reviewCount`，写回 `books`，列表页零聚合成本。

**展示位置**

- 书籍详情页：评分概览（平均分 + 星级 + 条数）+ 前 3 条 + 「查看全部 N 条」。
- 全部书评页：分页列表、排序（最新/最有用）、我的评论置顶可编辑。

**验收标准**

- 同一账号重复提交不会产生第二条，而是更新原评论。
- 隐藏一条 5 星评论后，书籍平均分与条数同步变化。
- 未登录用户只能看，不能写、不能点赞（点赞引导登录）。
- 关闭/删除自己的评论后，概览数字同步。

### F5 书籍推荐栏目

**用户故事**：作为读者，打开首页就能看到「可能适合我」的书，而不是从 1000 本里翻。

**推荐位**

1. 首页「为你推荐」横滑卡片（6 本）+ 「查看更多」。
2. 推荐列表页：20 本/批，可「换一批」。

**算法（冷启动友好，纯规则，无需训练）**

候选池 = 当前有可借库存的书（`stocks` 任一地点 > 0），上限 200 本。

打分（满分 100）：

| 维度   | 权重 | 计算                                      |
| ---- | -- | --------------------------------------- |
| 分类偏好 | 35 | 用户历史借阅中出现该分类的占比 × 35                    |
| 作者偏好 | 15 | 借过同作者的书给满分                              |
| 热度   | 20 | `borrowCount / 池内最大 borrowCount` × 20   |
| 口碑   | 20 | `ratingAvg / 5` × 20（无评分按 3 星折算，避免压制新书） |
| 新书   | 10 | 上架 ≤ 30 天给满分，否则按天数线性衰减                  |

**过滤**：剔除用户已借过（含在借）、已评论过的书；剔除已隐藏/下架书；同一作者最多 2 本。

**理由文案**：按命中权重最高的维度生成——「因为你在读『科技』类」「你借过刘慈欣的书」「本馆热门」「读者好评 4.6 分」「新书上架」。

**管理干预**：`settings.recommendPicks` 中的书**无条件置顶**（运营精选），并标注「馆员推荐」。

**冷启动**（未登录/无借阅历史）：热度 50% + 口碑 40% + 新书 10%，即「热门 + 高分 + 新书」。

**验收标准**

- 未登录用户也能看到推荐（不报错，走冷启动）。
- 推荐结果不含用户正在借阅的书。
- 「换一批」返回不同集合（offset 递进，池子不足时允许重复并提示「已为你推荐全部」）。

## 5. 数据模型

### reviews

```js
{
  _id, bookId, bookTitle,
  openid, userName, avatar, anonymous: false,
  rating: 1-5, content: '5-500 字',
  likeCount: 0, likedBy: [openid],
  status: 'approved' | 'hidden',
  reply: { content, openid, createdAt } | null,
  createdAt, updatedAt
}
```

### notifications

## 7. 安全与权限

1. 新增集合权限一律设为「**所有用户不可读写**」，仅云函数可访问；客户端不出现 `wx.cloud.database()` 直查新集合。
2. 所有写操作在云函数内校验：`openid` 必须存在；管理员操作统一走 `isAdmin(OPENID)`；本人操作校验文档 `openid === OPENID`。
3. 群发通知接收者上限 500，避免一次写入超时；发送记录单独留痕（`senderOpenid` + `createdAt`）。
4. CSV 导出接口做管理员校验 + 行数上限，避免被当作数据导出通道。
5. 评论内容长度/敏感词服务端强校验，前端校验仅用于提示。
